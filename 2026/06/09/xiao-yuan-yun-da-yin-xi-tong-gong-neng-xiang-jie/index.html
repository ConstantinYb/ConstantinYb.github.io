3. 数据库设计

数据库名：print，共 12 张业务表 + xxl-job 调度表（独立库 xxl_job）。

所有业务表统一使用 deleted 字段（tinyint(1) DEFAULT 0）实现逻辑删除。

3.1 核心业务表关系

sys_user ──┬── sys_user_role ──── sys_role ──── sys_role_permission ──── sys_permission
           │        (RBAC用户角色)     (RBAC角色)      (RBAC角色权限)         (RBAC权限)
           │
           ├── file              (用户上传的文件)
           ├── order             (用户创建的订单) ──── order_file (订单-文件关联)
           ├── order_log         (订单操作日志)
           ├── account_log       (账户流水)
           ├── recharge           (充值记录)
           ├── refund             (退款单)
           ├── notification       (消息通知)
           ├── shop_audit         (开店申请)
           │
shop ──────┤ (owner_id → sys_user.id)
           │
sys_log ───┘ (系统操作日志，独立记录)

4. 认证与授权体系 (RBAC)

4.1 整体流程图

用户登录请求
    │
    ▼
LoginController.login()
    │
    ▼
LoginService.login()
    ├── 1. 查用户表验证用户名/密码
    ├── 2. 查 sys_user_role → 获取角色ID列表
    ├── 3. 查 sys_role → 获取角色编码列表 (roleCodes)
    ├── 4. 查 sys_role_permission + sys_permission → 获取权限编码列表 (permissions)
    ├── 5. 生成 JWT (包含 roleCodes, permissions)
    └── 返回 LoginResponse (token, roles, permissions, homePage)
    │
    ▼
前端存储 token → 每次请求带 Authorization: Bearer <token>
    │
    ▼
JwtFilter.doFilterInternal()
    ├── 解析 JWT 获取 userId, roleCodes, permissions
    ├── 构建 GrantedAuthority 列表
    │     ├── ROLE_ 前缀 → 角色（如 ROLE_ADMIN）
    │     └── 无前缀 → 权限（如 user:list）
    ├── 创建 UsernamePasswordAuthenticationToken
    └── 设置到 SecurityContextHolder
    │
    ▼
SecurityConfig 鉴权
    ├── URL 拦截：放行 /login/**, /user/register, /file/download/**
    ├── 其余请求需认证
    └── @PreAuthorize 方法级鉴权（如 hasAuthority('user:list')）

4.2 核心代码

JwtUtil 生成 Token（print_common/util/JwtUtil.java:39-45）：

public String generateToken(String username, Long userId,
                            List<String> roleCodes, List<String> permissions) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("userId", userId);
    claims.put("roleCodes", roleCodes != null ? roleCodes : Collections.emptyList());
    claims.put("permissions", permissions != null ? permissions : Collections.emptyList());
    return generateToken(claims, username);
}

JWT 中包含 userId、roleCodes、permissions 三个关键信息，有效期默认 7 天（604800000ms）。

LoginService 登录逻辑（print_admin/service/LoginService.java:43-116）：

public LoginResponse login(LoginRequest loginRequest) {
    User user = userService.lambdaQuery()
            .eq(User::getUsername, loginRequest.getUsername()).one();
    if (user == null) throw new RuntimeException("用户名或密码错误");
    if (!passwordEncoder.matches(loginRequest.getPassword(), user.getPassword()))
        throw new RuntimeException("用户名或密码错误");
    if (user.getStatus() == 1) throw new RuntimeException("该账户已被冻结");

    // 查 RBAC 角色
    List<Long> roleIds = sysUserRoleService.getRoleIdsByUserId(user.getId());
    List<SysRole> roles = sysRoleService.listByIds(roleIds);
    List<String> roleCodes = roles.stream().map(SysRole::getRoleCode).collect(Collectors.toList());

    // 查 RBAC 权限
    List<String> permissions = sysPermissionService.getPermissionCodesByRoleIds(roleIds);

    // 兼容旧版角色校验
    if (loginRequest.getRole() != null) {
        String requiredRoleCode = mapRoleToCode(loginRequest.getRole());
        if (requiredRoleCode != null && !roleCodes.contains(requiredRoleCode))
            throw new RuntimeException("角色不匹配");
    }

    // 生成 JWT + 构建响应
    String token = jwtUtil.generateToken(user.getUsername(), user.getId(), roleCodes, permissions);
    // ...
}

JwtFilter 认证过滤器（print_common/filter/JwtFilter.java:34-91）：

@Override
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain) {
    String token = getTokenFromRequest(request);  // 从 Authorization 头取 Bearer token
    if (StringUtils.hasText(token)) {
        // 解析 JWT
        String username = jwtUtil.getUsernameFromToken(token);
        Long userId = jwtUtil.getUserIdFromToken(token);
        List<String> roleCodes = jwtUtil.getRoleCodesFromToken(token);
        List<String> permissions = jwtUtil.getPermissionsFromToken(token);

        // 构建权限列表
        List<SimpleGrantedAuthority> authorities = new ArrayList<>();
        for (String roleCode : roleCodes) {
            authorities.add(new SimpleGrantedAuthority("ROLE_" + roleCode.toUpperCase()));
        }
        for (String perm : permissions) {
            authorities.add(new SimpleGrantedAuthority(perm));
        }

        // 设置 Security 上下文
        UsernamePasswordAuthenticationToken authentication =
            new UsernamePasswordAuthenticationToken(userId, null, authorities);
        SecurityContextHolder.getContext().setAuthentication(authentication);
    }
    filterChain.doFilter(request, response);
}

4.4 角色兼容机制

由于前端可能传旧的 role 整数参数（0=客户, 1=老板, 2=管理员），后端通过 mapRoleToCode() 将其映射为 RBAC 的 role_code：

// LoginService.java:121-128
private String mapRoleToCode(Integer role) {
    switch (role) {
        case 0: return "customer";
        case 1: return "shop";
        case 2: return "admin";
        default: return null;
    }
}

登录响应中，role 字段通过 roleCodes 反推：

if (roleCodes.contains("admin")) response.setRole(2);
else if (roleCodes.contains("shop")) response.setRole(1);
else response.setRole(0);

5.4 RBAC 角色更新

// UserController.java:102-117
private void updateUserRole(Long userId, Integer role) {
    String targetCode = mapRoleToCode(role);
    SysRole targetRole = sysRoleService.getOne(
            new LambdaQueryWrapper<SysRole>().eq(SysRole::getRoleCode, targetCode));
    // 物理删除旧角色关联（绕过 @TableLogic）
    sysUserRoleMapper.physicalDeleteByUserId(userId);
    // 插入新角色关联
    SysUserRole sur = new SysUserRole();
    sur.setUserId(userId);
    sur.setRoleId(targetRole.getId());
    sysUserRoleService.save(sur);
}

注意： 使用物理删除而非逻辑删除，因为 sys_user_role 表有唯一约束 uk_user_role (user_id, role_id)，逻辑删除会导致重复插入时报 DuplicateKeyException。

// FileController.java:44-92
@PostMapping("/upload")
public Result<File> upload(@RequestParam("file") MultipartFile file) {
    // 1. 确保 E:/print/file/ 目录存在
    Path dir = Paths.get(uploadPath);
    if (!Files.exists(dir)) Files.createDirectories(dir);

    // 2. 生成 UUID 文件名（保留原始扩展名）
    String storedName = UUID.randomUUID().toString() + ext;

    // 3. 保存到本地磁盘
    Path target = dir.resolve(storedName);
    file.transferTo(target);

    // 4. 自动解析页数（PDF/Word/PPT/Excel/TXT）
    int pageCount = PageCountUtil.count(target, originalName);

    // 5. 记录到数据库
    File fileEntity = new File();
    fileEntity.setUserId(userId);
    fileEntity.setFileName(originalName);
    fileEntity.setFileUrl(storedName);     // 存 UUID 名，不存全路径
    fileEntity.setFileSize(file.getSize());
    fileEntity.setPageCount(pageCount);
    fileService.save(fileEntity);
}

6.3 页数自动识别（PageCountUtil）

PageCountUtil.java 支持以下文件格式：

格式解析方式说明
PDFPDFBox PDDocument.getNumberOfPages()精确页数
DOCX/DOCPOI XWPFDocument + 元数据优先读元数据，否则按字符数估算（2500字符/页）
PPTX/PPTPOI XMLSlideShow.getSlides().size()幻灯片数 = 页数
XLSX/XLSXSSFWorkbook.getNumberOfSheets()工作表数
TXT行数 ÷ 60 = 页数按60行/页估算
图片直接返回 1JPG/PNG/BMP/GIF/WEBP

@XxlJob("autoCancelOrderHandler")
public void autoCancelOrderHandler() {
    // 查询 status=0 且 createTime 超过30分钟的订单
    LocalDateTime deadline = LocalDateTime.now().minusMinutes(30);
    List<Order> unpaidOrders = orderService.list(
            new LambdaQueryWrapper<Order>()
                    .eq(Order::getStatus, 0)
                    .lt(Order::getCreateTime, deadline));

    // 逐笔取消（使用乐观锁：eq status=0 防止并发问题）
    for (Order order : unpaidOrders) {
        orderService.update(new LambdaUpdateWrapper<Order>()
                .eq(Order::getId, order.getId())
                .eq(Order::getStatus, 0)        // 乐观锁
                .set(Order::getStatus, 4)
                .set(Order::getUpdateTime, LocalDateTime.now()));
    }
}

public class MinioService {

        minioClient.putObject(PutObjectArgs.builder()
