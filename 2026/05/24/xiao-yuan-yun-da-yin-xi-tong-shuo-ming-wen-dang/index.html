三、功能实现详解

1. 用户认证（登录/登出/JWT）

流程： 前端提交 username + password + role → 后端验证 BCrypt 密码 → 从 RBAC 五表查询角色和权限 → 生成 JWT（含 userId、roleCodes、permissions）→ 返回 token + 用户信息 → 前端存入 localStorage → 后续请求通过 Axios 拦截器自动携带 Authorization: Bearer <token> → JwtFilter 解析 token 设置 SecurityContext → 从 SecurityUtils.getCurrentUserId() 获取当前用户。

6. 客户下单流程（4 步骤）

流程：

  1. 选择文件： 从已上传文件列表中勾选 → 有 0 页文件时显示黄色警告
  2. 选择店铺： GET /shop/list 获取营业中店铺 → 单选
  3. 打印配置： 纸张大小(A4/A3) + 色彩(黑白/彩色) + 单双面 + 份数 + 取件方式(自取/配送) → POST /order/calculate 计算价格
  4. 确认下单： 展示订单摘要 → POST /order/create 创建订单（status=0 待支付）

价格计算逻辑： 从 shop.price_config JSON 中按 {paperSize}{Color}{Side} 拼接 key（如 a4BlackSingle）获取单价 → 单价 × 总页数 × 份数 = 总金额

四、数据库表关系（RBAC 五表）

sys_user ──< sys_user_role >── sys_role ──< sys_role_permission >── sys_permission

用户登录时：

  1. sys_user_role 查用户的角色 ID 列表 → 2. sys_role 查角色编码（customer/shop/admin）→ 3. sys_permission 通过 sys_role_permission 关联查出权限编码 → 4. 写入 JWT claims → 5. JwtFilter 解析后注入 SecurityContext。

五、订单状态流转

0(待支付) ──支付──> 1(待接单) ──接单──> 2(打印中) ──完成──> 3(已完成)
  │                  │
  └──取消──> 4       └──拒绝──> 4(已取消)

所有状态变更均记录 updateTime，支付/接单/完成分别记录 payTime/acceptTime/completeTime。
